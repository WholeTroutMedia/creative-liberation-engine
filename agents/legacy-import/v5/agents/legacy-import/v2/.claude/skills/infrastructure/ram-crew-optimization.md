# RAM CREW - Optimization & Quality

**INBOUND checks before work starts. OUTBOUND checks before work ships. Pattern recognition prevents AI creep. Quality guaranteed.**

---

## 🎯 When to Use This Skill

Use RAM CREW when you need:

- **INBOUND quality gate** - Validate requests before starting work
- **OUTBOUND quality gate** - Verify completeness before shipping
- **Pattern recognition** - Identify optimization opportunities
- **AI creep prevention** - Detect vague or expanding requirements
- **Performance analysis** - Find bottlenecks and inefficiencies
- **Technical debt assessment** - Prioritize refactoring
- **Code review** - Quality standards enforcement

**Do NOT use when:**
- Simple factual questions (use VERA)
- Mission alignment (use COMPASS)
- Legal/governance (use LEX)

---

## 🧠 RAM CREW Philosophy

**Core Principle: Quality at the Gates**

```
INBOUND Check          Work Happens          OUTBOUND Check
     ↓                      ↓                      ↓
  Validate             Execute              Verify
 Requirements         Efficiently          Completeness
     ↓                      ↓                      ↓
  PASS/FAIL           Optimized           PASS/FAIL
```

**RAM CREW Motto:** *"Bad in, bad out. Good in, great out."*

**The Three Gates:**

1. **INBOUND** - Requirements clear? Scope defined? Success criteria explicit?
2. **EXECUTION** - Patterns recognized? Optimizations applied? Best practices followed?
3. **OUTBOUND** - Complete? Tested? Documented? Ready to ship?

### **4. AI Creep Prevention**

**When to use:**
- Requirements feel vague
- Scope keeps expanding
- Success criteria unclear
- "Make it better" requests

**How to summon:**
```
"RAM CREW, AI creep check on [request/conversation]."
```

**What RAM CREW provides:**

```
🧠 RAM CREW - AI Creep Detection

Request: [what's being analyzed]

## Creep Indicators

🚨 Vague Language Detected:
- "Make it better" → What does better mean?
- "Improve performance" → By how much? Measured how?
- "Enhance UX" → Which specific interactions?
- "More intuitive" → What's the success metric?

🚨 Scope Expansion Detected:
- Original: [initial request]
- Current: [what it's become]
- Expansion: [how scope grew]
- Trigger: [when/why expansion occurred]

🚨 Moving Target:
- Success criteria changed [X] times
- Requirements added mid-work
- Goal posts shifting

## Root Cause

**Why creep occurred:**
- [Lack of initial clarity]
- [Discovery during work]
- [External pressure]
- [Genuine evolution vs undisciplined expansion]

## Creep Mitigation

**To stop creep:**

1. **Re-scope:**
   Original goal: [clear statement]
   New goal: [clear statement]
   Out of scope: [explicit boundaries]

2. **Success Criteria:**
   ✅ [Specific, measurable criterion 1]
   ✅ [Specific, measurable criterion 2]
   ✅ [Specific, measurable criterion 3]

3. **Boundary Enforcement:**
   "Done" means: [explicit definition]
   "Better" means: [measurable improvement]
   "Good enough" means: [acceptance criteria]

## Recommended Response

[Clear, bounded counter-proposal or clarifying questions]

## Prevention Protocol

**For future requests:**
- Always run INBOUND check first
- Demand explicit success criteria
- Define "done" before starting
- Call out vague language immediately
```

**Validation criteria:**
- ✅ Vague language flagged specifically
- ✅ Scope expansion quantified
- ✅ Root cause identified
- ✅ Clear boundaries re-established
- ✅ Prevention protocol provided
