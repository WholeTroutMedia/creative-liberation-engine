# /team-assemble Workflow — Universal Swarm Orchestration

## Core Philosophy
We do not operate as solo developers passing files back and forth. Handoffs are minimized. Instead, every task is handled by an **instant organization** — a virtual swarm of specialized roles working in parallel to execute, review, and validate the complete task load.

---

## 1. Domain Swarm Blueprints

### A. INFRASTRUCTURE & BACKEND SWARM
*   **System Architect:** Designs the logical topology, enforces schema contracts, and manages service configurations.
*   **Database Administrator:** Controls table schemas, optimizes query plans, manages data indexing, and runs migrations.
*   **Security Hardener:** Enforces zero-trust boundaries, audits keys/tokens, and runs penetration checkers (`SENTINEL`).
*   **Systems QA:** Verifies container states, port bindings, route accessibility, and service log health.

### B. FRONTEND LOGIC SWARM
*   **State Integrity Lead:** Designs and monitors the global data stores (Zustand, React state), preventing redundant re-renders.
*   **Component Builder:** Authors modular, reusable, type-safe React / HTML UI modules.
*   **API Integration Specialist:** Maps and connects backend services to the user interface.
*   **Frontend QA:** Validates UI outputs across device boundaries (Desktop/Tablet/Mobile) and runs linters.

### C. CREATIVE & VISUAL SWARM
*   **UI/UX Architect:** Audits layout scaling, container constraints, viewport bounds, and aspect ratios.
*   **Typographer & Asset Lead:** Controls typographic hierarchy, contrast accessibility, icon assets, and wrapping rules.
*   **Visual FX Director:** Directs color palettes, theme transitions, visual premium assets, and glassmorphic/dark modes.
*   **Kinetic Designer:** Crafts micro-animations, interaction feedbacks, loading states, and frame-rate integrity.

### D. STRATEGY & RESEARCH SWARM
*   **Domain & Trend Analyst:** Performs deep research on external systems, scraping references and indexing prior art.
*   **Technical Diligence Lead:** Profiles existing architectures, catalogs technical debt, and assesses software libraries.
*   **Cost-Arbitrage Specialist:** Models runtime compute/API economics, forecasting scaling costs and capacity constraints.
*   **Scribe Assembly Editor:** Compiles raw inputs from the swarm into structured report templates (e.g., CISO Board Brief, McKinsey Strategy).

---

## 2. Steps for Execution

### Step 1 — Intent Detection & Swarm Composition
- The Meta-Orchestrator parses the task description and selects the matching Swarm Blueprint.
- For compound tasks, a **cross-functional swarm** (e.g., Infrastructure + Frontend Logic) is dynamically instantiated.
- The lead agents are explicitly declared.

### Step 2 — Parallel Subtask Queueing
- The Orchestrator breaks down the main goal into parallel subtasks and populates `task.md`.
- Individual swarm roles are assigned to execute their respective tasks simultaneously inside separate sub-contexts.

### Step 3 — Cross-Audit loop
- Swarm roles peer-review each other's outputs in real time:
  - Frontend components are reviewed by the UI/UX Architect for scale bounds.
  - Database schemas are audited by the Security Hardener.
  - Research data points are checked by the Technical Diligence Lead.

### Step 4 — Unified Gated Validation
- The task cannot transition to `VALIDATE` phase or `/release` until all assigned swarm roles sign off on their deliverables.
- Heuristic checks (e.g., Lighthouse scores, design token audits, TypeScript builds) must pass 100% cleanly.
